# explicit OpenTelemetry instrumentation.

What you'll learn

You'll understand these concepts:

    Request
    
    ↓
    
    Span
    
    ↓
    
    Tracer
    
    ↓
    
    Span Processor
    
    ↓
    
    Azure Exporter
    
    ↓
    
    Application Insights

Those are the fundamental OpenTelemetry building blocks.

# I propose we do one small refactor

Instead of continuing with azure-monitor-opentelemetry, we'll use:

    fastapi
    uvicorn
    
    opentelemetry-api
    opentelemetry-sdk
    
    opentelemetry-instrumentation-fastapi
    
    azure-monitor-opentelemetry-exporter

Notice we are not abandoning Azure Monitor. We are simply replacing the convenience wrapper 
with the underlying OpenTelemetry components. The telemetry will still go to your 
existing Application Insights resource.

# I think this is actually a better learning path

Since you're doing this to learn Azure monitoring and OpenTelemetry—not just to get telemetry 
appearing in the portal—understanding the native SDK will pay off. It will also make it 
easier to recognise what configure_azure_monitor() is doing behind the scenes if you 
encounter it in other projects.

We'll rebuild the application with native OpenTelemetry from scratch, and I expect we'll 
have telemetry flowing into Application Insights within one or two iterations because every 
step will be explicit and easy to verify.
